# 07 — 종합계획 단계별 통합 흐름과 로컬 GraphRAG 데모

> 상태: 합성 자료 기반의 로컬 end-to-end 데모. 읽기 전용 로컬 웹 UI MVP를 추가했다. 실제 수집, Neo4j, 벡터 DB, 임베딩, LLM, 운영 배포용 인증·접근통제는 미구현이다.
> 전제: [05 G0/G1 작업 기준](05_G0_G1_작업기준_및_G2_착수.md)과 [06 공식 출처 후보 검토](06_G1_공식출처_후보_검토.md)에 따라 개별 출처 승인은 아직 완료되지 않았다. 아래 실행은 합성 fixture에만 한정한다.

## 1. 목적과 범위

이 문서는 PoC의 단계별 데이터 흐름을 현재 코드와 연결하고, 검수·근거 추적·검색·그래프 응답의 동작을 재현하는 절차를 정한다. 지금 구현된 그래프는 승인된 `JobPosting` 레코드에서 실행 중 메모리로 만드는 결정론적 property graph다. 이름에 GraphRAG가 포함되어도 Neo4j, 벡터 검색, 임베딩, LLM 생성 또는 운영 서비스가 구현된 것은 아니다.

데모가 보여주는 것은 다음 세 가지다.

- 합성 데이터도 명시적 opt-in 없이는 로드하지 않는 fail-closed 입력 경계.
- 검수 승인된 레코드만 검색·그래프화하고 원천 증거와 synthetic 표시를 함께 반환하는 흐름.
- 검색 결과가 없을 때 근거 없는 답변을 만들지 않고 abstain하는 동작.
- 브라우저에서 검색·지역 필터·품질 요약·출처 및 근거를 확인할 수 있는 읽기 전용 로컬 UI.

실제 시장 규모, 청년 선호, 구인난 원인 또는 정책 효과에 관한 결론을 이 데모에서 도출하지 않는다. 실제 자료로 전환하려면 G0 범위 확인 및 출처별 G1 승인·보존 조건 확인이 선행되어야 한다.

## 2. 종합계획 단계와 현재 구현의 대응

| 단계 | 입력·처리 | 현재 구현 | 운영 전제/미구현 |
| --- | --- | --- | --- |
| G0 범위 확정 | 권역·직무·기간·분석 단위·제외 기준 확정 | 승인 결정 기록 완료 ([08 문서](08_G0_범위_결정안.md)) | 승인 범위에 따른 실데이터 사용은 출처별 G1 승인 필요 |
| G1 출처 승인 | 권리자·허용 목적/필드·수집·보존·삭제 확인 | 출처 레지스트리 CSV 검증 | 후보 출처는 `pending`; 검증 통과 자체가 권리 검토를 대신하지 않음 |
| G2 파일럿 수집 | 승인된 범위에서 제한된 자료 취득 | 수집기 없음 | G0/G1 통과 전 실데이터 다운로드·적재 금지 |
| 정규화·품질 게이트 | JSONL 계약 검증, 중복·검수 상태 확인 | `load_jsonl`, `validate_posting`, `quality_report` | 실제 출처별 매핑·정제·수동 검수 파이프라인 없음 |
| 지식 그래프 | 공고를 출처·기업·직무·지역·기술·복지 관계로 표현 | `build_job_graph`의 메모리 객체 | 영속 그래프 DB, 스키마 마이그레이션, 동시성 없음 |
| 검색·응답 | 그래프 엔터티/키워드/하이브리드 검색, 근거·출처 제시 | `retrieve_graph`, `answer_with_graph`, `hybrid_search`, 읽기 전용 로컬 웹 UI MVP | 벡터 검색·검증된 랭킹·LLM 요약·운영 UI 인증/배포 없음 |
| 평가·운영 | 품질·검색 적합성·인용 정확성 검증, 삭제/감사 | 고정 합성 질의 평가기, 검색/evidence payload 회귀 테스트 | 테스트 실행 결과 확정, 실제 relevance 라벨·운영 모니터링·접근통제·삭제/감사 체계 없음 |

**진행 게이트:** G0 미확정 또는 출처별 G1 미승인 상태에서는 G2 실데이터 수집으로 넘어가지 않는다. 합성 fixture 실행은 구현 검증을 위한 별도 경로이며, 출처 승인으로 간주하지 않는다.

## 3. 로컬 실행

웹 UI 실행 방법과 공개 배포 제한은 [11 웹 UI MVP 실행 가이드](11_웹_UI_MVP_실행가이드.md)를 참조한다. GraphRAG 기능 구현·평가·API 의존 단계는 [12 문서](12_GraphRAG_기능구현_단계계획.md)를 참조한다.

저장소 루트에서 합성 레코드를 검색한다.

```bash docs/07_통합흐름_로컬_GraphRAG_데모.md
python -m src.app.cli --data data/demo_jobs.jsonl --allow-synthetic --query Python --region 부산
```

동일한 fixture로 결정론적 그래프 검색과 인용 가능한 evidence package를 확인한다.

```bash docs/07_통합흐름_로컬_GraphRAG_데모.md
python -m src.app.cli --data data/demo_jobs.jsonl --allow-synthetic --graph --query Python --region 부산
```

테스트를 실행한다.

```bash docs/07_통합흐름_로컬_GraphRAG_데모.md
python -m unittest discover -s tests -v
```

`--allow-synthetic`을 생략하면 합성 레코드는 검색 대상이 되지 않는다. 비합성 레코드는 `--source-registry`로 전달한 레지스트리에서 출처가 명시적으로 승인되어야 한다. 이 옵션은 로컬 로더의 게이트일 뿐 실제 권리 확인이나 승인 절차를 수행하지 않는다. 비밀키·개인정보·승인되지 않은 원문을 명령행이나 저장소에 넣지 않는다.

## 4. 그래프 모델과 검색 동작

`build_job_graph`는 `searchable(posting)` 조건을 통과한 레코드만 그래프에 포함한다. 공고 노드에서 출처, 직무, 지역, 요구 기술, 복지로 관계를 만들며, 기업이 있을 때는 기업 노드에서 공고로 `POSTED_JOB` 관계를 만든다. 관계에는 원천 `posting_id`, 해당 필드의 `Evidence`, 합성 여부를 보존한다. 현재 관계 유형은 다음과 같다.

| 관계 | 방향 | 증거 필드 |
| --- | --- | --- |
| `FROM_SOURCE` | 공고 → 출처 | 별도 필드 증거 미연결 |
| `HAS_ROLE` | 공고 → 직무 | `role_category` |
| `LOCATED_IN` | 공고 → 지역 | `region` |
| `POSTED_JOB` | 기업 → 공고 | 별도 필드 증거 미연결 |
| `REQUIRES_SKILL` | 공고 → 기술 | `required_skills` |
| `OFFERS_BENEFIT` | 공고 → 복지 | `benefits` |

키워드/그래프 데모 검색은 기존 결정론적 검색 경로를 사용한다. 추가된 하이브리드는 검수 승인 공고의 제목·직무·스킬·복지·본문·지역 필드를 가중 부분 문자열 매칭하고, 그래프 관계 일치 점수를 더해 결과를 정렬한다. 결과에는 매칭 단어·필드·채널·그래프 관계 경로와 원문 evidence를 반환하며, 지역 필터와 결과 상한을 적용한다. UI의 기본 모드는 하이브리드다.

현재 토크나이저는 공백 분리이고 검색은 부분 문자열 기반이다. 동의어·형태소·임베딩 의미 검색은 하지 않는다. 가중치는 초기 휴리스틱이며 품질 검증된 순위 모델이 아니다. `FROM_SOURCE` 및 `POSTED_JOB` 관계에는 별도 원문 evidence가 없으므로 관계 자체를 인용 증거로 해석하지 않는다. 고정 합성 질의로 키워드/그래프/하이브리드를 비교하는 오프라인 평가기는 `python -m src.app.evaluate`다. 합성 평가 점수는 실제 검색 품질 추정치가 아니다.

## 5. 품질·안전 확인 항목

- 입력 행은 JSON object여야 하고 데이터 계약 검증을 통과해야 한다. 중복 ID, 잘못된 JSON, 미승인 출처와 opt-in 없는 합성 행은 거부/격리한다.
- `review_status`가 승인되지 않은 레코드는 검색 및 그래프에 포함하지 않는다. 품질 보고서의 전체 건수와 승인 건수를 혼동하지 않는다.
- 급여 미기재·협의·추출 실패 상태는 숫자 0으로 바꾸지 않는다.
- 답변의 각 결과는 원천 레코드 및 사용 가능한 필드 증거를 통해 확인한다. 증거가 없으면 자동으로 내용을 보완하지 않는다.
- fixture의 synthetic 표시와 응답 안내 문구를 제거하지 않는다. 합성 결과를 실데이터, 대표 표본, 시장 통계로 제시하지 않는다.
- 실데이터 적용 전에는 개인정보 최소화, 접근 권한, 저장 위치, 보존 만료일, 삭제 책임자 및 원천 삭제 시 파생 데이터 처리 방안을 승인 기록에 둔다.

## 6. G2 착수 전 체크리스트와 다음 작업

- [ ] G0 책임자가 부산 실제 근무지·SW/AI 직무군·게시일 기준 90일·공고 단위·제외 기준을 확정한다.
- [ ] 출처별 G1 담당자가 공식 약관/서면 허가에서 수집·저장·정규화·내부 분석·근거 인용 조건을 확인한다.
- [ ] 보존기간, 만료일, 삭제 책임자와 원문/정제본/색인/백업 삭제 절차를 정한다.
- [ ] 승인 출처의 API/파일 스키마를 매핑하고 데이터 최소화·개인정보 제거 규칙을 문서화한다.
- [ ] 허용된 최대치 이하의 파일럿 상한(기준안 최대 50건)을 확정한 뒤 수집·검수한다.
- [ ] 품질 지표의 분모, 범위 적합성, 근거 보유율 및 중복 처리 결과를 검토하고 본 수집 Go/No-Go를 별도 결정한다.
- [ ] 검색 테스트 질의와 기대 결과를 합성/승인 자료별로 분리하고, 인용 충실도·검색 누락·부적합 결과를 평가한다.

다음 구현 후보는 (1) 출처별 원천 스키마 매핑 및 검수 이력, (2) 관계별 증거와 검색 hit 설명을 반환하는 계약, (3) 평가용 고정 질의 세트와 인용 검증, (4) 삭제·재색인 절차다. Neo4j, 벡터 DB, 임베딩, 외부 LLM을 추가하는 경우에는 해당 기술의 외부 처리 여부와 출처의 권한 조건을 별도 검토·승인하기 전까지 연결하지 않는다.

## 8. 상태 및 한계

이 문서는 현재 구현된 로컬 합성 데모의 흐름을 설명한다. 실제 출처 검증은 완료되지 않았고 실제 수집·저장·그래프 DB·벡터 검색·LLM 답변 생성·공용 서비스 배포는 수행하지 않았다. 로컬 웹 UI MVP는 시연용이며 인터넷에 안전하게 공개된 서비스가 아니다.
 구현 또는 승인 상태가 바뀌면 이 문서와 출처별 결정 기록을 함께 갱신한다.

> 합성 데모는 파이프라인 형태를 검증하기 위한 예시일 뿐 실제 채용시장에 대한 사실·추세·통계를 제공하지 않는다.

## 9. 실제 미구현 목록

- 공식 API에서 데이터를 가져오는 수집 adapter와 rate limit/retry 정책.
- 원천 레코드에 대한 버전 관리, 변경 감지, 재게시/중복 해소.
- 영속 그래프 저장소와 벡터 인덱스, 임베딩 모델 및 개인정보/외부처리 검토.
- 답변 생성 모델, prompt injection 방어, 응답 사실성·인용 검증 및 평가.
- 운영용 사용자 인증·권한, 인터넷 공개 배포, 보존·삭제 자동화. (로컬 시연 UI는 구현됨.)
- 실제 권한 승인 없이 사용할 수 없는 출처 연결 설정과 운영 자격 증명 관리.

미구현 항목은 현재 데모 실행에 필요한 전제 조건이 아니며, 승인과 별도 설계 없이 부분 구현을 실데이터 운영에 전용하지 않는다.

## 10. 문서 변경 원칙

각 단계의 상태는 `미구현`, `합성 데모`, `승인 대기`, `승인 완료`를 구분해 표시한다. 코드가 실행된다는 이유만으로 실데이터 수집이나 출처 이용 권한이 승인된 것처럼 서술하지 않는다. 변경 시 실행 명령, 테스트 결과, 실제 상태를 함께 갱신한다.

### 빠른 확인

- 기본 검색: JSONL 로드 → 계약/승인 게이트 → 품질 요약 → 키워드 검색.
- 그래프 데모: 동일 입력 → 메모리 그래프 생성 → 엔터티 우선 검색 → 인용 포함 결과 또는 abstain.
- 테스트: 합성 opt-in, 미검수 제외, 출처 승인 레지스트리, 근거 반환, 빈 결과 abstain.
- 아직 할 수 없는 것: 승인되지 않은 실데이터 접근, 외부 서비스 호출, 지속 저장, LLM 기반 자연어 답변.

실행 및 테스트 결과는 README의 현재 기준과 일치하도록 검증한다.
