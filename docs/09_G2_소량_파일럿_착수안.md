# 09 — G2 소량 파일럿 착수안

> 상태: **착수 준비 초안 / 데이터 실행 차단**. 08번의 G0는 초기 공고 분석 범위에 한정되며, 현재 방향인 개인 이력 기반 비교·추천 목적은 별도 범위 보완이 필요하다. 한국고용정보원 후보의 출처별 이용 권한·API 명세도 확인되지 않아 실제 G2 수집은 시작하지 않는다. 이 문서는 필요한 승인 후 실행 절차를 고정하기 위한 것이다.
> 선행 문서: [08 G0 분석 범위 결정안](08_G0_범위_결정안.md), [06 G1 공식 출처 후보 검토](06_G1_공식출처_후보_검토.md), [03 데이터 확보 및 품질 관리](03_데이터_확보_및_품질관리.md).

## 1. 현재 게이트 판정

| 게이트 | 판정 | 근거/남은 조건 |
| --- | --- | --- |
| G0 초기 공고 분석 범위 | `approved` | 부산 실제 근무지, SW/AI 직무군, 게시일 기준 직전 90일, 원천 공고 ID 단위로 확정 ([08 문서](08_G0_범위_결정안.md)); 개인화 추천 목적은 포함하지 않음 |
| G1 일반 프로젝트 내부 정책 | `approved` | 내부 PoC·최소 수집·외부 처리/재배포 금지에 관한 일반 정책 승인. 개인 이력 기반 추천의 목적·개인정보 처리 정책 승인으로 간주하지 않음 |
| G1 추천 목적 내부 정책 | `pending` | 추천 대상·입력·개인정보 처리·보존/삭제·사용자 고지 범위의 별도 검토/승인 필요 |
| G0 추천 목적 범위 보완 | `pending` | 개인 이력·희망 조건 비교, 추천 표시·정렬 및 사용자 범위의 승인 기록이 필요 |
| G1 한국고용정보원 출처 이용 권한 | `pending` | 사용자가 목록 API 명세를 제공했으나 이용조건·저장·추천 허용은 미확인. 인증키 발급은 출처 권한이 아님. 인증정보 없는 요청은 `authKey는 필수 입니다.` 응답만 확인했고 키 값은 읽지 않음 |
| G2 실제 취득 | `blocked pending G1` | 인증된 API 호출·공고 데이터 조회·샘플 요청·다운로드·적재를 하지 않음 |

이 문서에서 “준비”는 필드 목록·품질 기준·실행 안전장치를 계획하는 일만 뜻한다. 사용자가 목록 API의 필수 파라미터·XML 출력 필드 명세를 제공했고, 이를 바탕으로 격리된 XML 클라이언트를 만들었다. 모의 응답 테스트만 수행하며 권한 근거가 확보되기 전에는 인증키를 이용한 실제 호출·공고 데이터 조회·저장을 하지 않는다.

## 2. 파일럿 상한 및 표본 정의

- 파일럿 상한: **최대 50건 또는 제공자가 허용한 더 낮은 수량**. 권한 조건이 수집을 허용하지 않거나 필드·기간을 확인할 수 없으면 0건이며, 목표 수량을 채우려고 범위를 넓히지 않는다.
- 모집단 범위: 실제 취득 시점에 KST 기준으로 확정한 직전 90일 게시 공고. 정확한 시작일·종료일을 요청 전에 기록한다.
- 지역·직무: 부산 실제 근무지와 공고 내용상 명확한 SW/AI 직무만 주 분석 대상으로 분류한다. 출처가 이 조건을 식별할 수 없으면 추정하지 않고 제외/보류한다.
- 분석 단위: 출처의 원천 공고 ID 1개. 동일 ID 중복은 제거하고 다른 ID의 재게시 의심은 별도 집계한다.
- 급여: 원문·상태·단위를 보존한다. 비교 가능한 단위가 아닌 값은 숫자 집계에 넣지 않는다.

## 3. 실행 전 필수 승인 체크리스트

아래 항목이 모두 근거와 함께 확인되기 전에는 G2 실행 금지다.

- [ ] 출처의 정확한 데이터셋 식별자, 권리자/승인권자, 목록 및 상세(`callTp=D`) 최신 API 명세와 공식 약관을 확보했다.
- [ ] 부산 실제 근무지, 등록일/게시일, 직무, 원천 공고 ID, 필요한 근거 필드와 코드표의 의미·가용성을 문서로 확인했다.
- [ ] API 호출 방법, 인증 절차, 요청량·페이지 한도·속도 제한을 확인했다. 사용자가 제공한 명세에는 `startPage` 최대 1000, `display` 최대 100으로 안내되어 있으나 별도 호출량/속도 제한은 미확인.
- [ ] 추천 목적의 G0 범위 보완과 개인 이력 처리·사용자 고지에 대한 내부 정책 승인을 각각 기록했다.
- [ ] 목적, 요청 필드, 로컬 저장, 변환, 내부 분석, 검색·추천 결과 화면, 개인화 정렬 및 짧은 인용의 허용 범위를 각각 확인했다.
- [ ] 재배포와 외부 처리 조건을 기록했다. 현재 프로젝트 설정은 둘 다 금지다.
- [ ] 보존 기간, 파일럿 만료일, 원본·정제본·로그·백업 삭제 방법과 담당자를 확정했다.
- [ ] 개인정보 가능성·최소화 기준, 접근자, 저장 위치를 확인했다.
- [ ] 요청할 정확한 날짜 범위·필드·상한(최대 50건 이하)과 중단 조건을 기록했다.
- [ ] 권한 있는 승인자가 출처별 G1을 통과 처리했고, 레지스트리와 보충 결정 기록이 일치한다.

사용자는 인증키를 저장소 루트의 로컬 `.env`에 저장했다고 보고했다. 이 문서는 해당 파일을 읽거나 키 값을 기록하지 않는다. 출처별 G1 및 추천 목적 범위 승인이 확인되기 전에는 키를 이용한 API 호출·샘플 취득을 하지 않는다. `.gitignore`는 `.env`를 제외하지만, 이것만으로 자격 증명 안전이 보장되는 것은 아니므로 저장소 상태를 확인하고 값은 코드·문서·대화·fixture·로그에 복사하지 않는다. 키가 노출되면 즉시 폐기·재발급한다.

## 4. 필드 매핑 및 취득 계획

사용자가 제공한 목록 API 문서에서 필드명을 확인할 수 있으나, 의미·코드표·지역 실제성·게시일과 갱신일의 관계는 별도 확인이 필요하다. 목록 API에 긴 공고 본문/상세 직무기술은 제시되어 있지 않다. 상세 조회(`callTp=D`) 명세를 받기 전에는 상세 응답을 가정하지 않는다.

| PoC 필드 | 목록 API 필드/경로 | 추가 확인 사항 | 상태 |
| --- | --- | --- | --- |
| 원천 공고 ID | `wantedAuthNo` (구인인증번호) | 유일성·변경/재게시 관계 | 부분 확인 |
| 게시일/수집 기간 | `regDt` (등록일자); `minWantedAuthDt`, `maxWantedAuthDt` 날짜 필터 | 등록일과 게시일/구인인증일 관계, 형식·시간대·갱신 시 의미 | 부분 확인 |
| 제목/상세 내용 | `title`; 목록 응답에 본문 필드는 없음 | `callTp=D` 요청 필드·상세 응답과 본문 저장/인용 권한 | 부분 확인 |
| 실제 근무지 | `region`, `zipCd`, `strtnmCd`, `basicAddr`, `detailAddr` | 지역 코드표, 근무지와 회사 주소 구별, 부산 필터 정확도 | 부분 확인 |
| 직무/직종 | `jobsCd`, `title`, `indTpNm` | 직종 코드표 및 SW/AI 분류 적합성 | 부분 확인 |
| 급여 | `salTpNm`, `sal`, `minSal`, `maxSal` | 단위·범위/협의 표기·정규화 의미 | 부분 확인 |
| 상태·원문 링크·갱신 | `closeDt`, `wantedInfoUrl`, `wantedMobileInfoUrl`, `smodifyDtm` | 마감/활성 상태, URL 사용·표시, 수정값 형식 | 부분 확인 |

취득은 승인된 API 방식으로만 수행하며, 요청/응답 원문 저장 자체가 허용되는지 먼저 확인한다. 응답 데이터가 허용되지 않는 저장 위치나 필드를 포함하면 저장 전에 중단하고 담당자에게 확인한다. 재시도·페이지 반복은 명세의 한도 이내로 제한한다.

## 5. 품질·근거 평가 산출물

파일럿이 승인되어 실제 수행될 경우, 다음 수와 분모를 함께 보고한다. 합격 임계치를 결과를 본 뒤 임의로 조정하지 않는다.

- 요청·수신·형식 오류·권한/범위 제외 건수.
- 원천 ID 기준 중복 수와 서로 다른 ID의 재게시 의심 수.
- 부산 실제 근무지 판정 가능/불가 및 해당 비율.
- 게시일 확인 가능/불가, 90일 기간 내/외 건수.
- SW/AI 포함·제외·미분류 수와 표본 검수 결과.
- 필드별 결측/추출 실패/검수 대기 수 및 해당 분모.
- 승인된 추출 필드별 evidence 보유율과 원문 위치 확인 결과.
- 급여 상태별 건수, 단위별 분포 가능성. 비교 불가능한 단위는 합산하지 않음.
- 파일럿 저장 위치, 릴리스/변환 버전, 보존 만료일, 삭제 책임자.

50건 이하 파일럿은 기술·품질 가능성 확인 표본이며 시장 대표 표본이 아니다. 결과를 청년 선호, 전체 채용시장, 기업 수요 규모 또는 정책 효과로 일반화하지 않는다.

## 6. 승인 후 실행 순서 및 중단 조건

1. 체크리스트를 출처별로 완성하고 G1 상태를 `approved`로 기록한다.
2. 정확한 게시일 범위, 필드 allowlist, 요청 상한, 저장 위치, 만료·삭제일을 실행 기록에 고정한다.
3. 비밀관리 방식을 적용하고, 서비스키를 출력하지 않는지 검토한다. 별도 승인 없는 외부 API/LLM/임베딩 전송을 비활성화한다.
4. 승인된 최소 요청만 수행해 상한 이하의 표본을 취득한다. 각 실행의 요청 ID·시각·건수·문서/변환 버전만 비민감 로그에 남긴다.
5. 스키마·중복·기간·근무지·직무·근거 품질 검사를 실행하고 부적합 행은 격리한다.
6. 품질·권한·보존 결과를 검토해 본 수집(G3) 진행/보류를 별도 결정한다. G2 파일럿 승인은 대량 수집 승인이 아니다.

다음 중 하나라도 발생하면 즉시 중단하고, 영향 받은 데이터와 로그를 격리한다: 권한 범위 불일치, 미확인 필드 저장, 제공자 요청량 초과 위험, 개인정보 과다 수신, 출처/근거 추적 불가, 보존·삭제 조건 미충족, 키 노출.

## 7. 현재 요청 사항

G2 실행 차단을 해제하려면 한국고용정보원/Work24의 공개 API 명세와 이용조건 또는 권한 있는 제공자의 서면 답변이 필요하다. 특히 추천 목적의 G0 범위 보완, 로컬 저장·정규화·내부 분석·인용·개인화 비교/정렬·보존/삭제 허용 여부, 필수 필드 제공 여부를 확인할 수 있어야 한다. 프로젝트 관리자의 일반 승인과 사용자가 보고한 인증키 발급·로컬 `.env` 저장만으로는 출처 권한이나 G2 데이터 수집을 승인할 수 없다. 인증키 값은 문서에 기록하지 않으며, 필요한 승인이 확인되기 전까지 키를 사용하지 않는다.
