# 10 — 한국고용정보원 채용정보 API 이용조건 확인 요청안

> 상태: 제공기관 문의용 초안. G0 범위와 프로젝트 내부 정책은 승인되었으나, 이 문서는 출처 이용 허가가 아니다. 문의 회신 및 공식 약관으로 조건을 확인하기 전까지 API 키 발급·호출·샘플 취득·적재는 하지 않는다.
> 후보 안내 URL: https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do
> 후보 검색 목록: https://www.data.go.kr/tcs/dss/selectDataSetList.do?dType=API&keyword=%EC%B1%84%EC%9A%A9%EC%A0%95%EB%B3%B4

## 1. 문의 목적

한국고용정보원 채용정보 API가 부산 지역 SW/AI 채용공고의 내부 기술 PoC에 적합한지, 그리고 요청·저장·정규화·내부 분석·근거 표시를 어떤 조건으로 허용하는지 확인한다. 문의 단계에서는 실제 데이터, 인증키, API 응답 샘플을 요청하지 않는다.

## 2. 제공기관 문의문 초안

**제목:** 채용정보 API의 내부 PoC 이용 범위 및 데이터 보존 조건 문의

안녕하세요. 한국고용정보원 채용정보 API의 이용 조건을 확인하고자 문의드립니다.

저희는 승인된 범위에서 채용공고의 직무·요구 기술·근무조건을 원천 근거와 함께 검색·요약하는 내부 기술 PoC를 준비하고 있습니다. 범위는 부산광역시 내 실제 근무지가 확인되는 SW/AI 관련 공고, 게시일 기준 취득 시점 직전 90일, 공고 단위이며, 초기 파일럿은 제공기관이 허용하는 한도 내 최대 50건으로 계획합니다. 이 수량은 제안 상한이며, 제공기관의 허용량이 더 낮으면 그 조건을 따릅니다.

현재는 API 키 발급·API 호출·샘플 다운로드를 진행하지 않고 있습니다. 아래 사항에 대한 공식 문서 링크 또는 서면 안내를 부탁드립니다.

1. 해당 API의 정확한 데이터셋 명칭/식별자, 최신 API 명세 및 운영 제공기관/데이터 권리자.
2. 부산 실제 근무지, 게시일, 직무/직종, 원천 공고 ID, 제목·본문/상세내용, 급여가 제공되는지와 각 필드의 의미·갱신/재게시 방식.
3. 부산·직무·게시일 조건으로 필터링할 수 있는지, 페이지/요청량/속도 제한, 허용된 자동 호출 방식은 무엇인지.
4. PoC 목적의 API 응답 수신 외에 원문 응답의 로컬 저장, 정규화·파생 필드 생성, 내부 분석, 결과 화면 표시 및 짧은 원문 인용이 각각 허용되는지. 허용 시 출처 표시·인용 길이·사용자 범위 등 조건이 있는지.
5. 자료의 재배포와 제3자 외부 서비스(LLM·임베딩·호스팅 등) 전송 조건. 본 PoC는 별도 허가가 없는 한 재배포와 외부 처리를 하지 않을 예정입니다.
6. 허용 보존기간 및 이용 종료/철회 시 원문·정제본·색인·백업 삭제 요구사항과 삭제 완료 증빙 조건.
7. 개인정보 또는 담당자 연락처가 응답에 포함되는지, 해당 항목의 저장·마스킹·제외 조건.
8. 이용 신청/승인 및 인증키 발급 절차, 승인 주체, 서비스키의 보안·회전·폐기 조건.
9. 위 PoC 사용 범위에 별도 서면 허가나 추가 계약이 필요한지, 이용약관/라이선스의 적용 조항과 버전은 무엇인지.

위 내용 확인 전에는 실제 데이터를 취득하지 않겠습니다. API 키나 데이터 샘플은 이 문의에 포함하지 않습니다. 감사합니다.

## 4. 회신 후 처리

1. 회신과 적용 약관을 원문 그대로 보존할 수 있는지부터 확인하고, 프로젝트 결정 기록에는 비밀·개인정보를 제외한 문서 식별자와 조항만 남긴다.
2. 각 권한·기술 항목을 `yes/no/unknown`으로 분리해 [06 G1 후보 검토](06_G1_공식출처_후보_검토.md)에 기록한다.
3. 허가가 명확하고 G0 필수 필드·보존·삭제 기준이 충족될 때에만 권한 있는 승인자가 해당 출처를 `approved`로 판정하고 레지스트리를 등록한다. 불명확하면 `pending`, 불가능하면 `blocked`다.
4. 승인 후 별도 G2 실행기록에서 정확한 날짜·필드 allowlist·상한·보존만료일·저장 위치를 확정한다. 프로젝트 관리자의 승인만으로 API 호출을 개시하지 않는다.
