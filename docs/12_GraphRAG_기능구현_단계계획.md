# 12 — GraphRAG 기능 구현 및 의존 정보 계획

> 상태: 구현 기준안. 현재 앱은 합성 데이터에서 동작하는 읽기 전용 검색 UI와 결정론적 그래프 데모를 제공한다. 공공기관 API 이용 권한은 별도 확인 중이며 이 문서는 권한 승인이나 LLM 선정 결정을 대신하지 않는다.
> 선행: [02 15일 실행계획](02_PoC_15일_실행계획.md), [07 로컬 GraphRAG 데모](07_통합흐름_로컬_GraphRAG_데모.md), [11 웹 UI MVP](11_웹_UI_MVP_실행가이드.md).

## 1. 현재 기술 기준선

현재 구현의 GraphRAG는 운영형 GraphRAG가 아니라 **설명 가능한 검색 기준선**이다.

1. 승인된 출처·계약을 통과하고 검수 완료된 공고만 로드한다.
2. 공고에서 직무·지역·기술·복지 노드를 만들어 메모리 property graph를 구성한다.
3. 키워드 필드 매칭과 그래프 관계 일치를 함께 점수화하는 하이브리드 검색을 수행한다.
4. 순위 근거로 매칭 단어·필드·관계 경로·원문 evidence·출처를 반환한다.
5. UI에서 하이브리드 GraphRAG, 그래프 데모, 키워드 검색 모드를 구분한다.

임베딩·벡터 검색·LLM 답변 생성·외부 서비스 전송은 아직 사용하지 않는다. 점수 가중치는 초기 휴리스틱이며 실제 relevance 지표로 검증된 모델이 아니다. 현재 그래프는 각 요청에서 메모리로 구성하며 Neo4j 등 영속 그래프 DB가 아니다.

## 2. 종합계획에 따른 다음 구현 순서

### 단계 A — 검색 설명·평가 기준선 고정 (현재 진행)

- 고정 질의 세트와 기대 공고/evidence를 작성한다. 질의 유형: 기술 검색, 직무 검색, 지역 필터, 기술+지역 조합, 급여·복지, 무결과, 모호 질의.
- 키워드 검색과 그래프 검색 및 하이브리드 결과를 별도로 평가한다.
- 지표: Recall@k, Precision@k, MRR 또는 nDCG@k, 승인된 결과의 evidence coverage, 인용 원문 일치율, 무결과 abstention.
- 초기 합성 자료에서는 기능 회귀만 확인한다. 소량 합성 표본의 점수로 실사용 성능을 주장하지 않는다.
- 인덱스/검색 버전과 평가 질의 세트를 함께 기록해 데이터가 들어온 뒤 비교 가능하게 한다.

### 단계 B — 원천 필드 매핑 및 G2 파일럿

API 정보와 출처별 G1 승인이 도착한 후에만 수행한다.

- API 응답의 원천 필드를 현재 `JobPosting` 계약으로 매핑하고 코드/날짜/근무지 의미를 확인한다.
- 허용 필드 allowlist, 요청 상한, KST 날짜 범위, 저장 위치, 보존 만료·삭제를 먼저 기록한다.
- 승인된 한도 이내(현재 기준 최대 50건)로 취득하고, JSONL 격리·중복·검수·근거 추적을 수행한다.
- 결과를 본 뒤 임계치를 조정하지 않는다. 품질/근거와 평가 결과를 검토해 본 수집을 별도 승인한다.

### 단계 C — 의미 검색 비교 (선택적 벡터 검색)

하이브리드 기준선 평가에서 동의어·자연어 표현 때문에 미검색/순위 저하가 확인되고, 원문 또는 청크의 임베딩·저장·처리 권한이 확인될 때만 추가한다.

- 공고 전체를 무조건 벡터화하지 않는다. 최소 허용 텍스트, chunk ID, 공고 ID, 필드, 원문 위치, 데이터 버전을 연결한다.
- 로컬 임베딩 모델 또는 승인된 외부 임베딩 API를 비교하되, 개인정보/보존/외부 전송 조건을 먼저 검토한다.
- vector top-k와 lexical/graph 결과를 합칠 때 reciprocal rank fusion 등 재현 가능한 결합 방식을 실험하고, 고정 질의로 기준선과 비교한다.
- 승인되지 않은 원문을 외부 임베딩·LLM 서비스에 보내지 않는다. 출처 허가와 조직 보안 승인이 불명확하면 로컬 합성 자료에서만 실험한다.

### 단계 D — 근거 제한 답변 생성 (LLM은 후순위)

LLM은 검색·집계를 대신하지 않는다. 구조화 통계는 코드에서 계산하고, LLM은 승인된 검색 결과와 근거를 자연어로 서술하는 용도로만 제한한다.

- 먼저 검색 결과를 근거 패키지(JSON) 계약으로 고정하고, 답변의 모든 주장을 `posting_id`와 evidence에 연결한다.
- 근거 부족, 검색 0건, 권한 밖 질의에는 답변을 생성하지 않고 보류/거절한다.
- 프롬프트 인젝션·공고 본문 내 지시문은 비신뢰 데이터로 처리한다. 출력 검증·인용 검증·환각 회귀 테스트를 둔다.
- 외부 LLM API는 G1 출처의 외부 처리 권한, 공급자 보존/학습 정책, 리전, 접근통제와 보안 승인 후에만 선택한다.

### 단계 E — 저장소·UI·운영화

데이터 규모·팀 운영 역량·실행 환경을 확인한 뒤 메모리 그래프를 Neo4j 등으로 대체할지 결정한다. UI 외부 공개 전에는 인증, HTTPS/TLS, 권한 분리, 비밀관리, 감사/오류 로그, rate limit, 보존·삭제가 필요하다. 현재 MVP를 직접 공용 인터넷에 노출하지 않는다.

## 3. 현재 API 정보가 도착하면 필요한 자료

기관 API 정보는 아래 항목을 가능한 범위에서 제공하면 충분하다. 인증키·토큰·계정 비밀번호는 공유하지 않는다.

- 공식 상세 문서 URL/데이터셋 ID, OpenAPI 파일 또는 비밀정보를 제거한 명세 발췌.
- 목록/상세 응답 필드와 코드표: 공고 원천 ID, 게시일·갱신일, 실제 근무지, 직무/직종, 제목·본문, 급여, 원문 링크.
- API의 필터, 페이지/요청 상한, 인증 방식, 응답 형식, 오류·갱신 동작.
- 공식 약관/라이선스와 서면 회신: 로컬 저장, 변환, 내부 분석, 인용/화면 표시, 보존·삭제, 제3자 처리 허용 범위.
- API 문서 또는 회신의 기준일/버전. 불확실한 값은 `unknown`으로 유지한다.

기관의 이용조건을 검토한 뒤 source adapter와 실제 필드 매핑을 구현한다. API 응답 샘플은 그 전에 요청·다운로드하지 않는다.

## 4. LLM API 정보 및 보완 자료

**현재 단계에서 LLM API 키나 사업자 계정은 필요하지 않다.** LLM 호출 없이 검색·근거·평가 기준선을 구현할 수 있고, 외부 처리 금지 정책을 유지한다.

나중에 LLM 답변 생성을 검토하려면 다음을 먼저 정해야 한다.

1. 제공자/모델명, API 문서/버전, 사용 목적과 지원 리전.
2. 입력 데이터의 저장·학습 사용·보존·삭제 정책과 enterprise/API 설정.
3. 승인 데이터의 외부 전송 허용 근거, 필드 최소화와 비식별 기준.
4. 예상 요청량, 컨텍스트 한도, 단가/예산 상한, 타임아웃·재시도 제한.
5. API 키 주입·회전·폐기 방식. 키 자체는 저장소·문서·테스트·대화에 넣지 않는다.
6. 평가 가능한 출력 스키마, evidence 필수 조건, abstention/인젝션 안전 테스트.

이 자료가 없으면 provider-independent한 인터페이스·근거 JSON 계약만 먼저 준비하고 외부 연결은 하지 않는다.

## 5. 당장 진행할 수 있는 작업과 보류 항목

| 작업 | 현재 가능 여부 | 이유/완료 조건 |
| --- | --- | --- |
| 하이브리드 lexical+graph 검색 기준선 | 가능 | 합성 fixture만 사용, 점수·경로·evidence 노출 |
| 고정 평가 질의와 검색 회귀 테스트 | 가능 | 실제 데이터 일반화 없이 로컬 baseline 검증 |
| source adapter 실제 호출 | 보류 | 기관 API 명세와 G1 출처 권한 대기 |
| 실제 텍스트 임베딩/벡터 색인 | 보류 | 저장·색인·외부 처리 권한 및 품질 필요 |
| 외부 LLM API/실제 답변 생성 | 보류 | 출처 외부 처리 승인, 모델·보안 기준 필요 |
| 공용 웹 공개 | 보류 | 인증·TLS·배포 환경·접근통제 미구현 |

이 계획은 기술적 다음 단계를 진행하되, 허가되지 않은 실제 데이터·외부 서비스는 사용하지 않는 경계를 명시한다.
