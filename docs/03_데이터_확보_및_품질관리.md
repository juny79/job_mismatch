# 03 — 데이터 확보 및 품질 관리

> 근거: 종합계획서 3. 데이터 확보 및 품질 관리. 선행 기준은 [01 아키텍처](01_GraphRAG_프로젝트_아키텍처_초안.md)와 [02 15일 PoC 실행계획](02_PoC_15일_실행계획.md)이다.
> 상태: 절차·데이터 계약·승인 게이트 초안. 실데이터 출처와 사용 허가는 미확정이므로 현재 데이터 수집·크롤링을 수행하지 않았다.

## 1. 목적과 원칙

이 단계는 일정과 PoC 범위에 맞는 허용 데이터만 확보하고, 수집한 공고의 출처·원문·정규화 값·검수 이력을 연결하여 재현 가능한 품질을 확보한다. 표본 수를 먼저 채우기 위해 이용 조건을 생략하거나, 누락값을 추정으로 채우지 않는다.

- 출처별 수집·재사용·외부 처리 권한을 기록하고 승인되지 않은 출처는 fail-closed로 제외한다.
- 출처 응답 원문은 변경하지 않고 보존하며, 변환 데이터와 별도 버전으로 연결한다.
- 급여·기술·복지·지역·직무의 정규화 값마다 원문 위치나 인용을 기록한다.
- 수집된 행, 유효 행, 검수 완료 행, 분석 포함 행의 수를 각각 집계한다.
- 공개용·PoC 분석용 데이터에 개인 정보가 섞이면 격리 후 최소화/제외한다. 설문 개인 응답은 적재하지 않는다.
- API 약관·robots 지침·라이선스·개인정보 및 외부 전송 조건을 출처별 담당자가 확인하기 전에는 자동 수집을 시작하지 않는다.

## 2. 데이터 확보 게이트

| 게이트 | 확인 항목 | 결과/중단 조건 |
| --- | --- | --- |
| G0 범위 | 권역 1곳, 직무군 1~2개, 관측 기간, 질문·사용 목적, 담당자 | 합의 전 대상 데이터셋을 만들지 않음 |
| G1 출처 권한 | 데이터 소유자, 제공 약관/허가 문서, 수집 방법, 재사용·보관·삭제, 외부 처리 조건 | 근거 문서 또는 책임자 미확인 시 `blocked` |
| G2 소량 파일럿 | 허용된 파일/API 소량 샘플, 필드 가용성·중복·결측·갱신 가능성 | 범위 대표성과 품질이 미달하면 출처/범위 재선정 |
| G3 본 수집 승인 | 파일럿 결과, 수집량 상한, 저장 위치, 접근권한, 보존·삭제일, 외부 전송 여부 | 승인 기록 전 대량 수집·계정 발급 금지 |
| G4 분석 편입 | 레코드 검증, 중복 제거, 원문 근거, 수동 검수 상태 | 승인·검수 완료 레코드만 검색/집계에 포함 |

초기에는 승인된 CSV/JSON 파일 또는 공식 API를 우선 검토한다. 웹 페이지 자동 수집, 상용 채용사이트 크롤링, 외부 LLM/임베딩 호출은 각 출처의 명시적 허가와 보안 검토 없이는 실행하지 않는다. `data/source_registry_template.csv`는 기록 양식일 뿐 승인된 출처를 뜻하지 않는다.

## 3. 출처 레지스트리와 보존 기록

`data/source_registry_template.csv`의 한 행에 한 출처를 등록한다. `permission_reference`에는 허가 문서·약관 조항·승인 기록의 식별정보를 적고 비밀 링크나 토큰을 쓰지 않는다. `collection_allowed=yes`와 `status=approved` 외의 값은 승인으로 간주하지 않는다. 재배포 및 외부 처리 권한은 각각 따로 확인하며, 수집 허가가 곧 재배포/외부 전송 허가를 의미하지 않는다.

원본 스냅샷의 메타데이터에는 `source_id`, 수집 일시(UTC), 수집 실행 ID, 원본 파일/API 버전, 건수, 체크섬, 이용 조건 참조, 보존 만료일을 둔다. 원본 텍스트와 추출·정규화 산출물을 별도 저장하고, 데이터 릴리스 ID로 동일 버전의 그래프/벡터 인덱스와 연결한다. 비밀정보·API 키는 파일, 코드, 로그에 기록하지 않고 승인된 비밀 저장 경로로만 주입한다.

## 4. 데이터 계약 및 필드 정의

| 필드 | 요구 수준 | 규칙·품질 확인 |
| --- | --- | --- |
| `posting_id` | 필수 | 출처 ID와 원천 공고 식별자를 조합한 안정 ID. 중복 금지 |
| `source_id`, `source_name` | 필수 | 승인된 출처 레지스트리의 ID와 연결 |
| `source_record_id`, `source_url` | 가능한 경우 | 원본 레코드/페이지 참조. 접근 제한 URL은 외부 노출하지 않음 |
| `collected_at`, `posted_at`, `expires_at` | 수집 시각 필수, 게시/마감일은 가능하면 확보 | ISO-8601 정규화. 원문 날짜도 함께 보존. 게시일 결측은 관측 기간 분석에서 제외/별도 집계 |
| `title`, `raw_text` | 필수 | 원문 보존. 파서가 바꾼 텍스트만 단독 원본으로 쓰지 않음 |
| `company_id`, `company_name` | 가능한 경우 | 확인된 법인/출처 ID 우선. 이름만으로 기업 동일성을 추정하지 않음 |
| `region_raw`, `region`, `location_basis` | 근무지 원문 필수, 정규화는 검수 | 시·군·구와 PoC 권역 매핑 근거 구분. 주소 추정 금지 |
| `role_raw`, `role_category` | 원문 필수, 분류는 검수 | 직무 분류 사전과 버전을 기록. 모호하면 미분류 |
| `salary.raw/status/minimum/maximum/unit` | 상태 필수 | `reported`, `not_stated`, `negotiable`, `not_applicable`, `extraction_failed`, `review_pending` 구분. 단위 미확정은 집계 제외 |
| `required_skills`, `benefits` | 추출 후보 | 원문 구절·위치와 필수/우대 여부를 기록. 사전 버전 기록 |
| `evidence[]` | 승인 레코드의 추출값에 필수 | 필드명, 짧은 원문 인용, 페이지/필드 위치. 원문 전체를 인용 필드에 복제하지 않음 |
| `review_status`, `reviewer`, `reviewed_at` | 필수 관리 필드 | `pending`, `approved`, `rejected`; 검수자·시각 기록 |
| `data_version`, `transform_version` | 릴리스 필수 | 입력 원본과 변환 코드·사전 버전을 역추적 |

결측은 빈 문자열 하나로 합치지 않는다. 수치 집계에서는 상태를 유지하고 `not_stated`를 0으로 바꾸지 않는다. 과거 값 보정이나 외부 데이터 결합은 별도 출처·변환 이력을 남기고 승인한다.

## 5. 품질 게이트 및 지표

### 5.1 레코드 처리 상태

`발견/수신 → 형식 검사 → 출처 권한 검사 → 스키마 검사 → 범위 검사 → 중복 검사 → 정규화 후보 → 원문 근거 연결 → 사람 검수 → 분석 편입/격리/제외` 순서로 관리한다. 검수 대기 자료는 사용자 검색과 통계에 노출하지 않는다. 잘못된 행을 조용히 버리지 않고 레코드 ID, 행 번호, 실패 사유를 별도 품질 보고에 기록한다.

### 5.2 품질 보고 지표

| 품질 차원 | 지표/보고 |
| --- | --- |
| 권한·추적성 | 승인 출처 비율, 출처 ID 누락, 원문·변환 버전 연결률 |
| 완전성 | 필드별 입력/미기재/추출실패/검수대기 건수 및 비율 |
| 유효성 | 날짜·급여 범위·단위·지역/직무 코드 검사 실패 수 |
| 중복성 | 동일 출처 ID + 원천 공고 ID 중복률, 중복 후보의 병합/제외 이력 |
| 일관성 | 정규화된 지역·직무·급여 단위와 원문 간 불일치 검수 수 |
| 근거성 | 승인 추출값 중 필드별 원문 근거 인용/위치를 갖춘 비율 |
| 범위 적합성 | 선택 권역·직무군·기간 안팎의 건수와 분석 제외 사유 |
| 검수 | pending/approved/rejected 수, 검수자·시각, 표본 재검수 불일치율 |

분모는 해당 필드가 적용 가능한 레코드 수로 정의하고 각 보고서에 분모를 표시한다. 초깃값으로 합격률을 임의 설정하지 않는다. 소량 파일럿 결과를 본 뒤 데이터 책임자와 필드별 임계치를 합의하고, 합의 전에는 결과를 `파일럿/미검증`으로 표시한다.

## 6. 검수 및 정규화 절차

1. 출처 레지스트리에서 해당 데이터의 수집 권한과 허용 방법을 확인한다.
2. 원본을 스냅샷으로 고정하고 건수·체크섬·수집 시각을 기록한다.
3. JSONL 스키마, 필수 필드, 날짜/급여 유형, ID 중복을 자동 검사한다. 실패 행은 격리한다.
4. 지역·직무·스킬·복지·급여 정규화는 원문과 별도 컬럼에 제안하고 용어 사전 버전을 기록한다.
5. 추출된 필드별 원문 근거를 확인하고, 표본 검수에서 정확도·오류 유형을 기록한다.
6. 사람이 승인/반려한 행만 `review_status=approved`로 전환하고 데이터 릴리스 버전을 태깅한다.
7. 재수집·수정 시 이전 버전과 차이를 보고하고, 승인된 교정만 새 버전으로 배포한다.

## 7. 보안·보존·삭제

원본 접근은 업무상 필요한 최소 인원에게 제한하고, 실제 회사/연락처/개인 식별 정보가 불필요하게 포함되면 추출 전에 마스킹 또는 제외를 검토한다. 설문은 개인 행을 적재하지 않고 승인된 최소 셀 집계만 사용한다. 보존 기간은 출처 약관·사업 요구에 맞춰 승인 단계에서 설정하며, 기간이 정해지지 않은 자료는 수집하지 않는다. 만료·철회 시 원본·정제본·그래프·벡터 색인·캐시·백업의 삭제 범위를 기록하고 삭제를 검증한다.

## 8. 현재 실행 상태와 다음 행동

- 출처 레지스트리 빈 템플릿과 fail-closed 검증기를 준비한다. 이는 법률 검토나 실제 수집 허가를 대체하지 않는다.
- 분석 권역·직무·기간, 출처, 책임자, 원본 보존기간이 미확정이므로 현재 실데이터는 수집하지 않는다.
- 다음 승인 미팅에서 G0/G1 값을 결정하고, 승인된 소량 샘플만으로 G2 파일럿을 실행한다.
- G2에서 필드 가용성·결측·중복·근거성 결과를 검토한 뒤, 합의된 기준과 수집량 상한으로 G3 승인을 요청한다.
