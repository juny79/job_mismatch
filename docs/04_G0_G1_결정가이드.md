# 04 — G0/G1 범위·출처 승인 결정 가이드

> 목적: 승인 미팅에서 PoC 분석 범위(G0)와 데이터 출처 이용 조건(G1)을 결정하고 기록한다.
> 상태: 결정 양식 및 진행 가이드. 아래 선택지는 논의를 위한 예시이며, 확정된 권역·직무·기간·출처·허가를 뜻하지 않는다. 결정과 권한 확인 전에는 실데이터를 수집·복사·적재하거나 외부로 전송하지 않는다.
> 선행 기준: [01 아키텍처](01_GraphRAG_프로젝트_아키텍처_초안.md), [02 PoC 실행계획](02_PoC_15일_실행계획.md), [03 데이터 확보·품질 관리](03_데이터_확보_및_품질관리.md).

## 1. 미팅 종료 시 산출물

1. G0 범위 결정서: 질문, 권역, 직무군, 관측 기간, 분석 단위·제외 기준, 책임자, 결과 해석의 한계.
2. G1 출처별 권한 결정표: 소유자, 허가 근거, 허용 수집 방법·필드·목적, 저장·변환·재사용·재배포·외부 처리 조건, 보존·삭제 조건.
3. 결정자·승인자·결정일·근거 문서 식별자·재검토일.
4. 각 출처 상태: `approved`, `blocked`, `pending`. pending/blocked 출처는 사용하지 않는다.
5. G2 파일럿 착수 여부, 최소 표본/필드, 수집 상한, 담당자.

미확인 항목은 추정하지 말고 `미확인`으로 기록해 담당자와 기한을 정한다. G0/G1 승인 전에는 합성 데모만 진행한다.

## 2. G0 — 분석 범위

### 2.1 분석 질문과 사용 목적

질문은 1~3개로 제한하고 공고 관측 데이터로 답할 수 있는지 확인한다. 관측 빈도를 청년 전체의 선호, 기업 구인난의 원인, 취업·정착 효과로 일반화하지 않는다.

검토용 질문 예시(확정안 아님):
- 선택 권역·기간의 승인 공고에서 어떤 직무와 기술이 관찰되는가?
- 급여가 명시되고 단위가 같은 공고는 몇 건이며, 그 하한은 어떻게 분포하는가?
- 특정 직무군 공고에 어떤 복지·근무 조건이 원문 근거와 함께 나타나는가?

| 결정 항목 | 회의에서 확정할 내용 |
| --- | --- |
| 핵심 질문(1~3개) | 미정 |
| 사용자와 의사결정 목적 | 미정 |
| 데이터로 답하지 않을 질문·해석 한계 | 미정 |
| 결과물·성공 판단 기준 | 미정 |

### 2.2 권역

- 먼저 권역 1곳을 선택한다: 예를 들어 부산광역시 전체, 창원시, 울산광역시 전체. 이는 선택지일 뿐 권고된 확정 범위가 아니다.
- 행정구역명과 가능하면 행정구역 코드로 경계를 고정한다.
- 기업 본사가 아니라 **실제 근무지**를 기준으로 할지 결정한다. 근무지 불명, 복수 근무지, 재택 공고 처리도 명시한다.
- 출처 데이터가 선택한 경계를 구분하지 못하면 범위를 넓히거나 해당 행을 범위 분석에서 제외한다. 주소 추정은 하지 않는다.

**기록:** 권역 ______ / 행정구역 코드 ______ / 위치 기준(근무지 등) ______ / 불명·복수 근무지 처리 ______

### 2.3 직무군

- 1~2개 직무군을 정하고 포함·제외 사례, 경계 사례, 미분류 처리 기준을 기록한다.
- 원문 직함과 정규화된 직무군을 별도 보존한다. 키워드 자동 일치만으로 모호한 직무를 확정하지 않는다.
- 분류 사전/매핑표 버전과 검수자를 지정한다. 실제 출처의 필드와 표현을 확인한 뒤 범위를 최종 고정한다.

**기록:** 직무군 ______ / 포함 직함 ______ / 제외·경계 사례 ______ / 미분류 처리 ______ / 사전 버전·검수자 ______

### 2.4 기간과 관측 정의

- 게시일 기준 시작·종료일을 명시한다. 게시일 누락 시 기간 분석 제외 또는 별도 집계 중 하나를 정한다. 수집일을 게시일로 대체하지 않는다.
- 재게시·갱신 공고의 중복 처리와 단면/주기 수집 여부를 정한다.
- 최근 3개월은 파일럿 계획 시 검토할 수 있는 예시일 뿐이다. 계절성, 출처 보유 기간, 질문에 맞춰 승인자가 결정한다.

**기록:** 게시일 시작 ______ / 종료 ______ / 게시일 누락 처리 ______ / 재게시 처리 ______ / 기준 시간대 ______

### 2.5 분석 단위·상한·제외 기준

- 기본 단위는 공고 1건이다. 공고 수를 기업 수·구인 인원으로 해석하지 않는다.
- 허용 수집량은 출처 권한 확인 후 출처별로 정한다. 미승인 상태로 샘플 파일을 받아 저장하지 않는다.
- 기간 밖, 중복, 위치 불명, 미분류, 급여 단위 불명, 개인정보 포함 행의 처리 및 품질 보고 분모를 정한다.
- 근거 없이 목표 건수나 합격률을 만들지 않는다. G2 결과 후 품질 임계치를 합의한다.

## 3. G1 — 출처별 이용 권한

### 3.1 후보 평가 순서

아래는 조사 순서이지 승인된 출처 목록이 아니다.

1. 공식 공개 데이터/API: 라이선스, API 약관, 재사용·저장 조건, 실제 필드 범위를 확인한다.
2. 기업·기관의 직접 제공 파일: 데이터 소유자와 서면 허가를 확인하고 목적·기간·삭제 조건을 합의한다.
3. 상용 구인 플랫폼: 자동 수집, 저장, 분석, 인용, 재배포 허가를 각각 권리자에게 확인한다. 공개 페이지라는 이유만으로 크롤링을 허용으로 보지 않는다.
4. 검색 결과·미러·제3자 파일: 원 출처와 권한을 확인할 수 없으면 `blocked`로 둔다.

API 키 발급이나 페이지 접근 가능 여부는 사용 허가가 아니다. robots 지침만으로 계약·저작권·개인정보·약관 검토를 대체할 수 없다.

### 3.2 출처마다 확인할 항목

| 영역 | 확인 질문 | 기록 |
| --- | --- | --- |
| 권리자·승인권자 | 데이터 소유자와 사용 조건을 승인할 권한자가 확인되었는가? | 미정 |
| 수집 방법 | 파일/API/수동 중 무엇이 허용되는가? 자동화, 빈도, 요청량 제한은? | 미정 |
| 목적·범위 | PoC 내부 분석 목적, 권역·직무·기간·건수가 허용 범위인가? | 미정 |
| 허용 필드·원문 | 제목·본문·회사·근무지·급여 등을 받을 수 있는가? 원문 저장·인용 제한은? | 미정 |
| 저장·변환 | 로컬 저장, 정규화, 파생 필드, 백업이 허용되는가? | 미정 |
| 내부 이용·공개 | 팀원·PoC 사용자에게 보여줄 수 있는가? 원문·인용·통계 공개는 별도 허용인가? | 미정 |
| 외부 처리 | LLM·임베딩·호스팅 등 외부 서비스 전송이 허용되는가? 지역·하위 처리 조건은? | 미정 |
| 보존·삭제 | 보존 만료일, 철회 시 원본·정제본·색인·캐시·백업 삭제 책임과 증빙은? | 미정 |
| 개인정보·보안 | 개인 연락처 등 포함 가능성, 최소화·격리·접근 통제 방식은? | 미정 |
| 증빙·재검토 | 근거 문서 식별자, 승인자·일자, 재검토/만료일은? | 미정 |

수집, 내부 분석, 재배포, 외부 처리는 각각 독립적으로 확인한다. `unknown`은 허가가 아니다. 허용이 불명확한 작업은 하지 않는다.

### 3.3 출처별 결정 기록(한 출처당 한 행/양식)

| 필드 | 결정값 |
| --- | --- |
| `source_id`, 출처명, 공식 URL | 미정 |
| 데이터 소유자, 담당자, 승인권자 | 미정 |
| 허가 문서/약관 조항/승인 식별자 | 미정(비밀 링크·토큰 제외) |
| 허용 수집 방식, 빈도, 요청량 상한 | 미정 |
| 허용 목적, 권역·직무·기간, 필드 | 미정 |
| 수집·저장·변환·내부 분석 | yes / no / unknown 및 조건 |
| 재배포 / 외부 처리 | 각각 yes / no / unknown 및 조건 |
| 보존 일수·만료일·삭제 방식 | 미정 |
| 개인정보·접근 통제 조건 | 미정 |
| 승인자·승인일·재검토일 | 미정 |
| 상태·미해결 항목·담당자·기한 | pending / blocked / approved |

`data/source_registry_template.csv`는 일부 권한 필드만 담는다. 허용 방법·목적·세부 필드·요청량·삭제 증빙 등은 별도 결정 메모/근거와 연결해 보관한다. 레지스트리의 `approved` 표시는 법률 검토나 실제 권리 확인을 대신하지 않는다. 권한 있는 승인자가 근거를 확인한 뒤에만 등록한다.

## 4. 75분 승인 미팅 진행안

1. **0–10분 — 목적·경계:** 질문, 사용자, 결과 해석의 한계를 정한다.
2. **10–25분 — G0 범위:** 권역·근무지 기준·직무·게시일 기간·분석 단위·제외 기준을 결정한다.
3. **25–50분 — G1 출처:** 후보별 권리자·근거·수집법·필드·저장·외부 처리·재배포·삭제 조건을 점검한다. 모르면 unknown으로 기록한다.
4. **50–65분 — 보안·운영:** 저장 위치, 최소 접근 인원, 개인정보 처리, 만료·철회 삭제 책임을 정한다.
5. **65–75분 — 승인·액션:** 승인자와 근거를 재확인하고 미해결 항목의 담당자·기한 및 G2 착수 여부를 결정한다.

참석 역할: 업무 목적 책임자, 데이터 소유자/권한 있는 제공자, 데이터 책임자, 필요한 경우 보안·개인정보 담당자, 구현 담당자. 한 사람이 여러 역할을 맡아도 승인권자와 기록 책임자는 분명히 한다.

## 5. Go/No-Go 확인

### G0 통과
- [ ] 질문과 사용 목적이 정해졌고 공고 데이터로 답할 수 있다.
- [ ] 권역·근무지 기준·직무군·게시일 기간·중복·누락 처리가 기록되었다.
- [ ] 책임자와 승인자가 범위 결정서를 확인했다.

### G1 출처별 통과
- [ ] 데이터 권리자와 승인권자를 확인했다.
- [ ] 근거 문서를 확인했고 수집 방법·목적이 명시적으로 허용된다.
- [ ] 허용 필드, 원문 저장·변환, 내부 이용, 재배포, 외부 처리를 각각 확인했다.
- [ ] 보존·삭제, 저장 위치, 접근권한, 개인정보 대응을 기록했다.
- [ ] 레지스트리 상태와 보충 결정 메모가 일치하고 승인 기록이 있다.

G0 또는 해당 출처의 G1이 미통과면 수집·계정 발급·자동화·외부 전송을 시작하지 않는다. 승인 출처가 없으면 합성 데모만 유지한다.

## 6. 미팅 직후 실행 순서

1. 범위 결정서와 권한 근거 식별자를 작성하고 승인권자 확인을 받는다.
2. 승인된 출처만 `data/source_registry_template.csv`에 등록하고, 비밀정보는 기재하지 않는다.
3. 허용 조건을 구현 담당자에게 전달한다. 범위 밖 필드·방법·외부 전송은 기술적으로도 비활성화한다.
4. 승인된 최소 샘플로 G2 파일럿을 계획한다. 샘플 취득 전에 수량 상한·저장·삭제일을 확정한다.
5. 파일럿 결과(필드 가용성, 결측, 중복, 근거성, 범위 적합성)를 분모와 함께 보고하고 G3 본 수집 승인을 별도로 요청한다.

## 7. 회의 전 준비 체크리스트

- [ ] PoC 질문 후보와 기대 사용자/의사결정자를 준비한다.
- [ ] 후보 권역·직무군 및 경계 사례를 준비하되 최종 선정은 출처 가용성과 함께 한다.
- [ ] 각 후보 출처의 공식 약관/라이선스/허가 문서 식별자와 권리자 연락 경로를 준비한다. 허가가 확인되지 않은 데이터 샘플은 준비·복사하지 않는다.
- [ ] 저장 위치, 접근할 사람, 외부 도구 사용 여부, 보존·삭제 책임자를 확인한다.
- [ ] 결정권자가 참석 가능한지 확인하고 미해결 질문에 담당자·기한을 붙일 준비를 한다.
