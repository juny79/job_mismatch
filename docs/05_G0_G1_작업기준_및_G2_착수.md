# 05 — G0/G1 작업 기준 및 G2 착수안

> 상태: G1 내부 정책은 프로젝트 책임자인 사용자가 대화에서 승인했다. G0 범위는 작업 기준안으로 사용하며, 출처별 권리·약관 검증과 승인은 미완료다. 본 문서는 제3자 이용 허가나 법률 검토를 대신하지 않는다.

> 관련: [03 데이터 확보·품질 관리](03_데이터_확보_및_품질관리.md), [04 G0/G1 결정 가이드](04_G0_G1_결정가이드.md).

## 1. G0 제안 기준

| 결정 항목 | 작업 기준안 | 적용 경계 |
| --- | --- | --- |
| 목적 | 승인된 공고에서 직무·기술·근무조건을 근거와 함께 검색·요약하는 내부 PoC | 청년 전체 선호, 구인난 원인, 정책 효과를 추론하지 않음 |
| 권역 | 부산광역시 내 실제 근무지가 확인되는 공고 | 부울경 전체로 확장하지 않음. 본사 주소만 부산인 공고는 포함하지 않음 |
| 직무군 | SW/AI 관련 직무 1개 그룹: 소프트웨어 개발·데이터/AI 직무 중 내용이 명확한 공고 | IT 영업·일반 사무·모호한 공고는 제외 또는 미분류. 로봇/제어 등 확장은 파일럿 후 별도 결정 |
| 관측 기간 | 수집 실행일 직전 90일에 게시된 공고, 단면 스냅샷 | 실제 날짜는 승인된 샘플 취득 전에 KST 기준으로 기록. 게시일 누락은 기간 분석에서 제외·별도 집계 |
| 분석 단위 | 출처 내 원천 공고 ID 기준 공고 1건 | 동일 ID 중복은 제외. ID가 다른 재게시 의심 행은 후보로 표시 후 검토 |
| 포함/제외 | 부산 근무지가 확인되는 해당 기간 공고 포함. 경력 요건으로 청년 적합성을 추정하지 않음 | 이력서·개인 구직자 데이터·설문 원자료는 범위 밖. 위치·직무가 불명확하면 주 분석에서 제외 |
| 급여 | 원문·상태·단위를 보존하고 명시된 비교 가능한 단위만 집계 | 미기재·협의·단위 불명은 0으로 대체하지 않음 |
| 공개·처리 | 내부 PoC만. 외부 LLM·임베딩·호스팅 전송 금지. 외부 공개·재배포 금지 | 별도 서면 허가 및 보안 검토가 먼저 필요 |

이 범위는 단계 진행을 위한 **작업 기준안**이다. 사용자 요청으로 G1 정책 승인은 기록했으나, 이는 G0의 사업 범위 승인이나 개별 출처의 이용 허가를 뜻하지 않는다. G0 변경이 필요하면 범위 결정에 기록하고, 그 외에는 이 기준으로 출처 후보를 검토한다.

## 2. G1 승인 정책과 출처별 판정

### 승인된 프로젝트 출처 정책

- 우선 검토: (1) 공식 채용정보 파일/API, (2) 기관·기업이 직접 제공하는 파일. 이는 후보 유형일 뿐 승인된 출처 목록이 아니다.
- 상용 채용 사이트 자동 수집, 로그인·접근 제한 우회, 검색결과/미러 파일은 명시적 허가가 확인되지 않으면 사용하지 않는다.
- API가 공개되어 있거나 페이지에 접근할 수 있다는 사실만으로 본문 저장·변환·인용·재사용 권한을 가정하지 않는다.

### 출처마다 따로 확인할 권한

| 확인 항목 | 기록할 결정 |
| --- | --- |
| 소유자·승인권자 | 권리자, 담당자, 실제 승인 권한자 |
| 근거 | 공식 약관/라이선스/서면 허가의 식별자와 확인일 |
| 수집 | 파일/API/수동 중 허용 방법, 빈도·요청량 상한, 목적·기간 |
| 데이터 | 허용 필드, 원문 보관, 정규화·색인·짧은 근거 인용 허용 여부 |
| 이용 | 내부 분석·화면 표시, 재배포, 외부 처리를 각각 `yes/no/unknown`으로 기록 |
| 보안·보존 | 개인정보 조건, 저장 위치·접근자, 만료일·삭제 방법·책임자 |
| 승인 상태 | 승인자·승인일·재검토일 및 `approved/blocked/pending` |

기본값은 내부 분석도 허가 확인 후에만 진행, 재배포 `no`, 외부 처리 `no`이다. `unknown`은 허가가 아니다. 보존 기간이 정해지지 않았거나 삭제 책임자가 없으면 보류한다. 출처가 허용하는 기간보다 긴 보관은 하지 않는다.

### 승인 기록과 현재 판정

- **승인 범위:** 이 문서의 G1 프로젝트 내부 기본정책(허용 출처 유형, 수집·저장 최소화, 재배포 금지, 외부 처리 금지, 출처 조건에 따른 보존·삭제).
- **승인자:** 사용자(프로젝트 책임자라고 본인이 명시). 실명/직함은 제공되지 않아 기재하지 않음.
- **승인 근거:** 본 대화에서 사용자가 “G1 정책에서 현재 이 프로젝트를 진행하는 본인인 내가 승인”한다고 명시함. 정확한 승인일은 대화 기록을 프로젝트 회의록에 옮길 때 기록할 것.
- **승인되지 않은 범위:** 특정 데이터 제공자와 그 약관, 제3자 권리, 출처별 수집 권한, 법률·개인정보 검토.

**현재 판정:** G1 내부 정책은 승인되어 다음 단계로 진행한다. 단, 개별 출처는 권리자·근거·허용 조건 확인 전까지 `pending`이며, 실데이터 취득·수집·적재는 하지 않는다. 출처가 승인되기 전에는 `data/source_registry_template.csv`에 임의로 `approved`를 등록하지 않는다.

## 3. 다음 실무 작업

### A. 범위 확인 미팅 — PoC 책임자, 30분

1. 위 표에서 부산 실제 근무지 / SW·AI 1개 그룹 / 게시일 기준 직전 90일 / 공고 1건 단위 안을 확인·수정·보류한다.
2. 포함·제외 경계 사례와 결과 해석 한계를 기록한다.
3. 확인자, 결정일, 보류 항목 담당자·기한을 기록한다. 이를 완료하면 G0 작업 범위를 고정한다.

### B. 출처 후보 검토 — 1차 후보 식별 완료

공식 공공데이터포털에서 한국고용정보원 제공 `채용정보 API - 채용정보`를 후보로 식별했다. 상세 검토 기록과 공식 검색 URL은 [06 G1 공식 출처 후보 1차 검토](06_G1_공식출처_후보_검토.md)에 있다. 이는 후보 식별일 뿐 승인이나 이용약관 확인이 아니다.

다음으로 데이터 담당자가 상세 페이지와 최신 약관을 확인해 부산 실제 근무지·게시일·직무·본문 필드, 저장·분석·인용 허용 범위, 요청량, 보존·삭제를 체크리스트에 기록한다. 직접 제공 파일 후보는 권한 있는 담당자의 서면 허가가 있을 때만 추가 검토한다. 근거 확인 전에는 샘플 요청·다운로드를 하지 않는다.

### C. 출처별 G1 판정 및 등록

권한 있는 승인자가 근거를 확인하고 허용 목적·방법·필드·보존·삭제를 승인한 출처만 레지스트리에 등록한다. 권한 조건 일부가 불명확하면 해당 출처는 `pending` 또는 `blocked`이며 샘플도 취득하지 않는다. 승인 확인은 법률/개인정보 담당자 검토를 대체하지 않는다.

### D. G2 소량 파일럿

G0와 적어도 한 출처의 G1이 모두 통과한 뒤에만 진행한다. 첫 파일럿 상한은 **최대 50건 또는 출처가 허용한 더 낮은 한도**로 제안한다. 취득 전에 정확한 날짜 범위, 필드, 요청량, 저장 위치, 보존 만료일을 기록한다. 품질 보고는 필드 결측·중복·지역/직무 범위 적합성·근거 보유율을 각각 분모와 함께 계산하고, 결과를 본 뒤 G3 본 수집 여부와 기준을 결정한다. 표본이 적어도 임의 수집량 확대는 하지 않는다.

## 4. Go/No-Go

- **G0 통과:** 질문·사용 목적·권역·직무·기간·단위·제외 기준에 책임자가 서명/확인.
- **G1 출처별 통과:** 권리자와 근거 확인, 허용 수집법·필드·저장/이용·외부 처리·재배포·보존/삭제 조건 기록 및 승인.
- 하나라도 미통과면 해당 실데이터 수집·저장·자동화·외부 전송은 시작하지 않는다. 승인 출처가 없으면 합성 데모만 유지한다.
- 미팅 결과는 출처별 결정표와 근거 식별자에 남긴다. 비밀 토큰·접근 자격증명은 문서나 CSV에 기재하지 않는다.
