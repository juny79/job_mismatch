# 13 — GraphRAG 일자리 추천 시스템 전환·통합 업그레이드 계획

> 상태: **합성 자료 기반 비저장 이력-공고 매칭 vertical slice 진행 중**. 개인은 직접 입력하거나 브라우저에서 TXT/Markdown/PDF/DOCX 키워드 추출로 정보를 제공할 수 있다. PDF/DOCX 해석은 CDN 라이브러리를 사용한다. 실데이터 이용 권한·추천 품질·운영 안전성이 확보됐다는 의미는 아니다.
> 선행 기준: [08 G0 분석 범위 결정안](08_G0_범위_결정안.md), [09 G2 소량 파일럿 착수안](09_G2_소량_파일럿_착수안.md), [11 웹 UI MVP](11_웹_UI_MVP_실행가이드.md), [12 GraphRAG 기능 구현 계획](12_GraphRAG_기능구현_단계계획.md), [14 개인 이력 기반 전환안](14_개인이력_기반_채용공고_미스매칭_추천_전환안.md).

## 1. 목표 전환

개인이 직접 제공하고 확인한 이력 정보와 구직 희망 조건을 승인·검수된 채용공고와 비교해 미스매칭과 확인 필요 항목을 설명하고, 근거가 있는 후보를 제시한다. 원문 이력에서 자동 추출한 내용은 사용자 확인 전까지 사실로 간주하지 않는다. 추천은 취업 성공이나 채용 가능성을 예측하지 않으며, 이력의 미기재는 역량 부족을 뜻하지 않는다.

## 2. 현재 기준선

| 영역 | 현재 상태 | 후속 필요사항 |
| --- | --- | --- |
| 범위·권한 | 부산 실제 근무지·SW/AI·직전 90일 G0 기록. 추천 목적 G0 보완과 출처별 G1은 pending; 실데이터 G2 차단 | 추천 목적 범위 승인, 추천 표시까지 포함한 출처별 권한 확인 |
| 고용24 API | 사용자가 목록 XML 명세를 제공했고 분리된 목록 클라이언트·모의 전송 테스트를 추가함. 앱·DB 미연동; 키 열람·인증된 API 호출 없음 | 상세 명세·코드표·이용조건 및 G1/G2 승인 후에만 데이터 연동; 키는 환경변수 비밀로 유지 |
| 데이터 | 합성 JSONL, 계약 검증, 오류/중복 격리, 검수/evidence 필드 | 허가된 필드·최신성·마감·삭제 반영 |
| 검색·추천 | 키워드/그래프/초기 하이브리드 검색, 결정론적 조건 매칭 | 승인 자료 relevance 평가와 사용자 정정 |
| UI | 로컬 UI, 단계형 질문, 비저장 추천 흐름, TXT/MD/PDF/DOCX 키워드 후보 추출 | 개인정보 자동 제거, OCR, 사용성 평가 |
| 운영 | 로컬 시연 전용 | 접근 통제·보존/삭제·장애 대응 등 별도 승인 |

PDF는 PDF.js, DOCX는 Mammoth를 CDN에서 필요할 때 내려받아 브라우저에서 처리한다. 원문 파일은 서버로 보내지 않으며, 추출된 키워드만 추천 요청에 포함된다. 오프라인에서는 TXT/Markdown을 사용한다. 스캔 PDF OCR과 구형 DOC는 지원하지 않는다. 단계형 챗봇은 규칙 기반이며, 전문 이력서 파싱·개인정보 자동 제거·LLM 자유 대화·영속 프로필은 구현되지 않았다.

## 3. 추천 기능 계약

- 세션 기반 비저장 입력을 우선하고, 민감·보호 특성을 추천 변수로 수집·추론하지 않는다.
- 승인 출처·검수 상태·확인 가능한 모집 상태·필드 evidence가 있는 공고만 후보로 평가한다.
- 필수 조건은 먼저 적용하며 미일치·미확인은 제외한다. 선호 조건은 일치 상태와 함께 결정론적으로 설명한다.
- 이력 기술과 공고의 근거 있는 요구 기술을 비교해 일치, 이력 미기재(확인 필요), 공고 측 미확인을 분리한다.
- 근거·최신성이 불충분하거나 후보가 없으면 추천을 보류한다. 점수를 취업/합격 확률로 표현하지 않는다.

### 현재 구현 진행 기록

- `src/retrieval/recommend.py`는 검수 승인·모집 중·근거 확인 가능한 후보만 평가한다. 급여 비교 단위는 `만원/연`이다.
- `/api/recommend` 요청은 메모리에서만 처리하며 프로필과 조건을 저장하지 않는다.
- 브라우저는 TXT/Markdown/PDF/DOCX에서 고정 기술 사전 키워드를 후보 추출한다. PDF는 최대 50페이지, 파일은 최대 5MB로 제한한다. 스캔 PDF OCR·구형 DOC는 지원하지 않는다.
- 합성 추천 회귀 세트는 기능 동작만 확인하며 실제 추천 품질을 입증하지 않는다.

**미완료:** Work24 클라이언트의 앱/DB 연동과 인증된 실호출, 목록 필드의 도메인 매핑, 상세(`callTp=D`) 명세 확인, 개인정보 자동 제거, 자유 대화형 LLM 추출, 동의어/숙련도·프로젝트 맥락 검수, 모든 입력의 사용자 확인, 자격 조건, 실데이터 평가, 추천 목적 G0 보완, 출처별 G1/G2, 운영 보안 승인.

## 4. 데이터·정확성 요구사항

수집·저장·정규화·검색·추천 표시·인용·보존/삭제 권한을 출처별 확인한다. 게시·수정·마감·확인 시점을 보존하고, 불명확하면 최신이라고 단정하지 않는다. 추천 사유는 승인된 공고 evidence에 연결한다. 미기재·미상·추출 실패·검수 대기를 구분하고 임의로 일치/불일치 처리하지 않는다. 원천 수정·삭제·만료는 모든 인덱스와 캐시에 반영한다.

## 5. 평가와 출시 게이트

합성 fixture는 회귀 테스트에만 쓴다. 승인 데이터와 사람이 검토한 relevance 판단 없이 추천 품질 주장을 하지 않는다. 필수 조건 위반, evidence 정확성, 만료 공고 노출, 결측의 과장, 무결과 시 abstain을 고정 세트에서 검증한다.

| 게이트 | 통과 조건 | 실패 시 |
| --- | --- | --- |
| 추천 범위·정책 | 목적·대상·입력·제외 특성·보존 정책 결정 | 개인 추천 구현 보류 |
| 출처별 G1 | 추천 표시를 포함한 필드 권한과 최신성·삭제 조건 확인 | 실데이터 취득·연결 금지 |
| 합성 vertical slice | 조건 필터·근거 설명·abstain 회귀 테스트 | 공개 범위 확대 보류 |
| G2·오프라인 평가 | 승인 범위 취득, 품질 검수 및 고정 relevance 평가 통과 | 격리 후 재검토 |
| 사용자 파일럿 | 동의·개인정보·보안·지원 및 사용성 검증 | 내부 테스트로 제한 |
| 운영 출시 | 인증·권한·TLS·모니터링·보존/삭제·장애 대응 승인 | 공용 배포 금지 |

## 6. 다음 단계

1. 프로젝트 책임자가 추천 목적과 초기 범위, 비저장 원칙을 결정하고 G0 기록을 보완한다.
2. 목록 API 클라이언트는 합성 응답 모의 테스트에 한정한다. 출처별 G1에서 개인화 추천 표시, 필드 의미, 최신성, 보존·삭제 권한을 확인하고 별도 G2 실행 승인을 받기 전에는 인증된 호출이나 실데이터를 사용하지 않는다.
3. 현재 합성 vertical slice의 조건·evidence 회귀 테스트를 실행한다. 이는 동작 검증이지 실사용 추천 품질의 증명이 아니다.
4. G1 통과 후 제한 G2를 별도로 승인하고, 검수와 고정 오프라인 평가를 통과한 뒤 사용자 파일럿을 검토한다.
5. 현재 로컬 서버를 인터넷에 직접 공개하지 않는다. 운영 보안·개인정보·삭제 체계는 별도 승인 전까지 미구현으로 둔다.

이 문서의 작성이나 코드 구현만으로 G0 범위가 자동 확장되거나 출처 이용이 승인되는 것은 아니다.
